# Інформаційна система планування заходів енергоаудиту

Клієнт-серверна інформаційна система планування заходів енергоаудиту, призначена для обліку об'єктів енергоаудиту, проведення аудитів, розрахунку інтегрального індексу пріоритетності енергоефективних заходів та контролю споживання енергоресурсів.

Основні сутності системи: **об'єкти енергоаудиту** (`AuditObject`), **енергоаудити** (`EnergyAudit`), **енергоефективні заходи** (`Measure` із життєвим циклом `PROPOSED → APPROVED → IMPLEMENTATION → COMPLETED`) та **записи споживання ресурсів** (`ConsumptionRecord`). Через графічний інтерфейс JavaFX користувач може переглядати таблиці, виконувати CRUD-операції, перевіряти предметні обмеження переходів станів та запускати фоновий імпорт даних споживання з CSV-файлу.

## Технології

* **Java 21** – основна мова розробки серверної та клієнтської частин.
* **Maven** – збірка модулів `server` і `client`, керування залежностями та запуск тестів.
* **Servlet API 4.0.1** та **Apache Tomcat 9.x** – обробка HTTP-запитів і розгортання серверного WAR-архіву.
* **MySQL / JDBC** – реляційне збереження даних та взаємодія з БД на рівні DAO.
* **Jackson** – серіалізація та десеріалізація JSON між клієнтом і сервером.
* **JavaFX** – настільний графічний інтерфейс користувача та фонове виконання задач (`Task`).
* **JUnit 5** – модульне тестування серверної бізнес-логіки.
* **Git** – контроль версій.

## Підготовка бази даних

1. Встановіть та запустіть сервер **MySQL** (або сумісний MariaDB, наприклад у складі XAMPP).
2. Відкрийте **phpMyAdmin** (або будь-який SQL-клієнт) та імпортуйте кореневий файл `database.sql`. Скрипт створить базу даних `energy_audit` у кодуванні `utf8mb4` із початковими тестовими записами.
3. Переконайтеся, що в базі `energy_audit` створено 4 таблиці:
   * `audit_object`
   * `energy_audit`
   * `measure`
   * `consumption_record`
4. За потреби налаштуйте локальні параметри підключення до БД (`URL`, `USER`, `PASSWORD`) у класі `DBUtil` серверного модуля відповідно до конфігурації вашого локального MySQL-сервера (реальні паролі не зберігаються у публічному репозиторії).

## Запуск сервера

Команди Maven виконуються з каталогу `server`:

```bash
cd server
mvn clean test
mvn clean package
```

1. Після успішної збірки скопіюйте згенерований WAR-файл із каталогу `server/target/` (наприклад, `energy-audit-server.war`) у теку `webapps/` сервера **Apache Tomcat 9.x**.
2. Запустіть Tomcat і переконайтеся, що в логах немає помилок розгортання або підключення до MySQL.
3. Перевірте доступність API у браузері, перейшовши за контрольним GET-маршрутом (наприклад, `http://localhost:8080/energy-audit-server/objects`) – у відповідь має повернутися коректний JSON-масив об'єктів.

## Запуск JavaFX-клієнта

Перед запуском клієнта мають працювати **MySQL** та розгорнутий у **Tomcat** серверний модуль.

З кореня репозиторію виконайте:

```bash
cd client
mvn javafx:run
```

* У разі помилок підключення або статусу `404` перевірте, чи запущений Tomcat і чи збігається назва контексту WAR-файлу.
* Запускати клієнт потрібно саме з робочого каталогу `client/`, оскільки відносний шлях до CSV-файлу (`sample-data/consumption_records.csv`) обчислюється від нього.

## Тестування

Модульні тести **JUnit 5** розміщені в `server/src/test/java/ua/edu/nupp/kpp/server/CourseworkTest.java` і запускаються без потреби в Tomcat чи MySQL:

```bash
cd server
mvn clean test
```

Набір містить **12 unit-тестів**, які перевіряють:
* розрахунок фактора перевищення F1 (нижня межа `0.0` без перевищення та верхня межа `100.0` при надмірному перевищенні);
* обчислення інтегрального індексу пріоритету та відхилення значення фактора, більшого за `100`;
* правила життєвого циклу заходів у `MeasureService` (дозволені послідовні переходи, заборона стрибка через стани та заборона відкоту з фінального стану);
* серверну валідацію моделей `AuditObject`, `EnergyAudit` та `ConsumptionRecord`.

## CSV-імпорт

* **Шлях до файлу:** `sample-data/consumption_records.csv` (відносно каталогу `client/`).
* **Кодування:** `UTF-8`.
* **Формат:** роздільник `;`, 4 поля – `object_id;energy_type;amount;period`.
* **Маршрут обробки:** CSV-файл читається фоновим завданням `ImportConsumptionRecordsTask` (JavaFX `Task`) і надсилає кожен запис через HTTP-клієнт на сервер (`Servlet → Service → DAO → MySQL`), без прямого JDBC-доступу з клієнта.

**Порядок виконання:**
1. Запустіть MySQL, Tomcat та JavaFX-клієнт.
2. Переконайтеся, що `object_id` у `consumption_records.csv` відповідає реально чинному `id` у таблиці `audit_object`.
3. Відкрийте вкладку **«Споживання»** та натисніть **«Імпортувати CSV»**.
4. Простежте за `ProgressBar`, міткою статусу та автоматичним оновленням таблиці після завершення імпорту.

> **Увага щодо повторного імпорту:** перевірка на дублікати рядків при імпорті не реалізована, тому повторне натискання кнопки додасть ті самі записи в таблицю `consumption_record` ще раз із новими `id`.
